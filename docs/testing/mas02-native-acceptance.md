## 本轮修复

1. `main.dart`：通知初始化不再挡住首次迁入页和业务首帧。
2. `InstallationMigrationService`：先限制暂存目录权限，让 VACUUM 自己创建目标库。
   原生 SQLite 拒绝已存在的空目标文件；FFI 单元测试没有暴露这一差异。
3. WAL checkpoint 改用 `rawQuery` 并检查 `busy=0`。Darwin 驱动的 `execute`
   拒绝返回结果行的 PRAGMA，即使 SQLite 报文是 “not an error”。

## 复测流程与剩余边界

复测必须重新分配测试 Bundle ID 和独立容器，使用合成数据库；不要将真实用户目录
代入测试脚本。使用系统面板授权测试源/目标，通过进程完整可执行路径限定 PID。
先完成小库迁入，再增加大文件，在部分复制后中断；核对指针和旧库校验值，然后重试。
本轮设置入口安排下次迁入已验证；大文件中断轮由测试夹具直接设置测试容器的
`request-installation-import` 标记，之后的目录选择与迁入均走真实 UI。

尚未覆盖：真实外接盘硬件拔插、Finder file promise/云端占位文件及视频拖入槽位、知识库与
MCP 各自完整业务链路、原生只读授权下的活动 WAL、生产 Bundle ID 的商店分发签名。
FFI 测试覆盖 WAL 快照，但不能代替原生 WAL 权限验收。没有触发任何排队付费请求，
因此这里也不声称完成付费任务重启恢复的端到端验收。MAS-02 保持未整体完成。
