你在「Joycai Image Tool」项目里工作。本轮只重做一个控件：**工作台右侧配置面板里的「分辨率」字段，以及它打开的尺寸选择器**。几何、色彩、玻璃档位、动效全部沿用 `00 设计系统`，宿主面板沿用 `A1 工作台-图像` 的右栏；本轮不新增颜色语义。

**请把本轮所有帧放进新文件 `A1c 尺寸选择器.dc.html`，控制在 200 KB 以内**（工程侧读取工具的上限是 256 KiB，超出部分会被静默截断），放不下就拆 `A1d`。帧号从 30a 起。

## 一、为什么重做

- 这个选择器原本只服务 gpt-image-2 一个模型，是一只居中的 460 宽对话框，从上到下堆了六段：自动卡片 → 预设 chip → 「比例 + 长边 + 计算」一行 → 「宽 × 高」一行 → 吸附提示 → 比例预览小方块 → 四条规则的通过 / 不通过清单。
- 现在同一个选择器要服务三家：**gpt-image-2 / 2.5、千问 qwen-image、万相 wan2.7-image(-pro)**。三家的「合法尺寸」是同一种盒子（边长网格、最长边、长宽比、总像素范围），只是数字不同；万相另有 `1K / 2K / 4K` 档位关键字；预设数量从 7 个涨到 15 个。
- 现状的具体问题，请逐条回应：
  1. **用户的心智是「比例 + 大小」，控件的第一公民却是宽高两个输入框。** 比例计算器是后加的，挤在中间一行，要点「计算」才生效，算出来的值再回填到下面一行——两行输入互相覆盖，谁是主谁是从不清楚。
  2. **预设是一堆无差别的 `1536×1024` 数字 chip**，看不出哪个是 16:9、哪个是竖版、哪个属于 2K。万相 pro 有 3 个档位 + 12 个像素预设，平铺就是一面数字墙。
  3. **档位关键字（1K / 2K / 4K）和像素预设混在同一个 Wrap 里**，但行为不同：点档位直接关窗提交，点像素预设只是填进输入框。
  4. **规则清单永远占四行**，全部通过时也是四行绿勾，纯噪音；不通过时又没有告诉用户「往哪改」。
  5. 预览小方块只有 80px，和输入没有联动手感（不能拖）。
  6. 「自动」卡片的含义因模型而异（见下），现在是同一句话。
  7. 每次改尺寸都要开一只模态框。常用的「换个比例、档位不变」应该更轻。

## 二、工程侧已定的事实（设计须遵守）

1. **取值只有三种**：哨兵（`auto` 或 `not_set`，每个模型二选一）、档位关键字（仅万相：`1K` `2K`，pro 多 `4K`）、自由 `宽×高`。最终写回的是一个字符串。
2. **哨兵的真实含义**，文案要诚实：
   - gpt-image-2：`auto` ＝ 交给模型决定。
   - 千问：`not_set` ＝ 本应用代为选择 1K 面积——文生图出 1024×1024；改图时**跟随输入图的比例**、缩到 1K 面积。（不发尺寸的话上游按 2K 出图、按 2K 计费，所以应用一定会发。）
   - 万相：`not_set` ＝ 发 `1K`。
3. **四条规则的数字**（选择器从模型声明里读，不写死）：

   | 模型 | 边长网格 | 最长边 | 长宽比 | 总像素 |
   | --- | --- | --- | --- | --- |
   | gpt-image-2 / 2.5 | 16 | ≤ 3840 | ≤ 3:1 | 0.66–8.29 MP |
   | qwen-image 2.0 / 3.0、edit-max / plus | 16 | 无 | ≤ 8:1 | 0.26–4.19 MP（512²–2048²） |
   | wan2.7-image | 16 | 无 | ≤ 8:1 | 0.59–4.19 MP（768²–2048²） |
   | wan2.7-image-pro | 16 | 无 | ≤ 8:1 | 0.59–16.78 MP（768²–4096²） |

   「最长边」一条在后三家不存在，规则区要能少一行。
4. **计算器的行为**：给定比例 + 长边，工程侧总能返回一个合法尺寸——长边吸附到 16 的倍数，越界时沿网格向最近的合法值走（1:1 @ 3840 在 gpt-image-2 上会降到 2880×2880；16:9 @ 1024 会升到 1088×608）。**被修正过的值必须让用户看见**，不能悄悄改。比例超出上限（如 gpt-image-2 上的 4:1）时无解，要明确说是哪条规则挡住了。
5. **比例输入**接受 `16:9`、`16x9`、`16/9`、`1.78`、`0.5625`；方向由写法决定（9:16 ＝ 竖）。
6. **官方推荐尺寸表**（万相的预设来源；千问的预设是同比例的 1K 面积值）：

   | 比例 | 1K | 2K | 4K（仅 pro） |
   | --- | --- | --- | --- |
   | 1:1 | 档位 `1K` | 档位 `2K` | 档位 `4K` |
   | 16:9 / 9:16 | 1696×960 | 2688×1536 | 4096×2304 |
   | 4:3 / 3:4 | 1472×1104 | 2368×1728 | 4096×3072 |

   也就是说预设天然是一张**「比例 × 档位」的二维表**，不是一维列表。是否按这个结构呈现由你决定。
7. **计费与尺寸挂钩**：千问按输出面积分 1K / 2K 两档计价，2K 约为两倍；万相按档位。应用里已有「按规格计费」（`D2b`）。选择器**可以**提示当前尺寸落在哪个计价档，但拿不到具体单价时不能编数字——请决定要不要这条提示、长什么样，并给出「无计费信息」时的退化。
8. **同家族里有不能自由输入的模型**：初代 `qwen-image / -plus / -max` 只收五个固定尺寸，用的是普通下拉，不进本选择器；基础版 `qwen-image-edit` 没有尺寸参数，整个字段不出现。这两种不需要画，但选择器的入口字段要和它们旁边的普通下拉、分段控件在同一列里对齐（高度、圆角、值的字体）。
9. **存量值会过期**：用户从 gpt-image-2 切到 wan2.7-image 时，上一个模型留下的 `3840×2160` 在新模型上不合法，工程侧会回落到哨兵。回落是静默的——请决定入口字段要不要在那一刻给一个轻提示。

## 三、需要你裁决的设计问题

- **容器**：居中对话框、从入口字段展开的锚定浮层（玻璃 float 档）、还是面板内原地展开？桌面与手机可以不同。右栏宽 300，手机上右栏本身已经是底部 sheet（别再叠一层模态 sheet 而不说明层级）。
- **主从关系**：比例 + 大小为主、宽高为精确微调？还是反过来？两者如何保持同步而不互相覆盖用户正在打的字（现状用「计算」按钮规避了这个问题，代价是多一步）。
- **「大小」的表达**：档位分段（1K / 2K / 4K）、长边数字、滑杆、还是组合？gpt-image-2 没有档位关键字，但用户同样在想「大概 2K」。
- **常用比例**怎么给：比例 chip 带形状缩略（横 / 方 / 竖一眼可辨）？自定义比例放哪？
- **预览**要不要变成可交互的（拖角改比例），还是保持只读但更大、画出合法范围的边界？
- **规则反馈**：全部通过时收成一行摘要（如 `2688 × 1536 · 16:9 · 4.13 MP`），不通过时只展开挡路的那一条并给出「改成 X」的一键修正？
- **轻量路径**：入口字段旁要不要直接放一个比例快捷切换，不开选择器就能换横竖？

## 四、需要的帧

默认桌面、亮色、宿主为 `A1` 右栏。

- **30a · 入口字段四态**：哨兵（三家文案各一）/ 档位关键字 `2K` / 自由尺寸 `2688×1536`（要不要同时显示 `16:9`？）/ 上一模型的值刚被回落。与同列的下拉、分段控件并排，确认对齐。
- **30b · 选择器 · wan2.7-image-pro · 常态**：内容最多的一家（3 档位 + 二维预设表 + 自定义）。这一帧定主结构。
- **30c · 选择器 · qwen-image-3.0**：无档位关键字、无最长边规则；哨兵文案是「跟随输入图比例」那一句；若采纳计价档提示，在这里画 1K → 2K 越线的那一刻。
- **30d · 选择器 · gpt-image-2**：`auto` 哨兵、四条规则齐全、预设含 3840×2160。确认三家是同一个控件。
- **30e · 自定义比例与修正**：输入 `21:9` + 长边 3000 → 吸附；输入 1:1 @ 3840（gpt-image-2）→ 被降到 2880，修正如何显形；输入 `4:1`（gpt-image-2）→ 无解态。三态并排。
- **30f · 宽高直接输入**：打字中（未吸附，可能暂时不合法）/ 失焦吸附后 / 不合法且给出一键修正。
- **30g · 暗色**：30b 与 30e 的无解态。
- **30h · 平板（600–1000）与手机（< 600）**：30b 的结构在两档宽度下如何成立；手机上与右栏 sheet 的层级关系。数字键盘弹起时哪些内容必须仍然可见。
- **30i · 动效标注**：打开 / 关闭、比例切换时预览形变、修正值的显形。用 `00` 的 M1 / M2 / M3，高频操作（连续点比例）不加过场。

## 五、硬约束

- **几何**：沿用 `00` 的圆角阶梯 4 / 6 / 10 / 16 / 22 / 28 与七档字号；入口字段与同列控件等高；像素数字一律 mono。
- **色彩**：不新增语义色。选中＝主色（作文字时用深墨）；不通过＝错误色，只用于挡路的那一条；修正提示＝辅助文字色，不用警告色。
- **玻璃**：若用浮层，走 `AppGlass` 的 float 档；内含输入框与可滚动内容的层按 `00` 的约定保持不透明底，别在模糊层上放密集表单。「减少视觉效果」开启时所有玻璃层不透明，布局不能依赖透出的背景。
- **文字**：不用 emoji。`1K / 2K / 4K`、`MP`、`px` 不翻译。
- **四语言**：简中、繁中、日、英；为英文和日文预留长度（`Longest edge` / `アスペクト比`）。文件末尾给 l10n 提取清单，注明哪些沿用现有 key（`imageSizeAuto`、`imageSizePresets`、`imageSizeCustom`、`imageSizeRatio`、`imageSizeLongEdge`、`imageSizeWidth`、`imageSizeHeight`、`sizeRuleMultiple16`、`sizeRuleMaxEdge`、`sizeRuleAspect`、`sizeRulePixels`），哪些新增。
- **可达性**：全键盘可完成（Tab 顺序、Enter 提交、Esc 取消）；触控目标 ≥ 44；比例缩略不能是唯一的信息载体（要有文字）。
- **三档宽度都要成立**：桌面 ≥ 1000、平板 < 1000、手机 < 600。

## 六、不在范围

其他家族的「比例下拉 + 档位分段」双控件（Gemini、Seedream、xAI、MiniMax——它们的接口收的就是比例和档位，不收像素）；视频面板；计费组编辑器本身；提示词扩写等同列的其他参数。
但请在标注里写一句：如果本轮的「比例 + 大小」结构将来要反向统一那几家的双控件，哪些部分可以直接复用。
