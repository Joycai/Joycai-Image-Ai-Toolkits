## 一、为什么改

- 模型有「类型」chip（对话 / 生图 / 视频 / 多模态），今天只用来过滤工作台的模型选择器。真正走哪个接口，是按「模型 ID」字符串猜的。
- 官方渠道的 ID 规范，猜得准。**中转站（New API 之类）的模型名是自由文本**（`nano-banana-pro`、`my-sora`、`img-fast`），猜不准。结果：生图模型被当成对话发出去；视频模型在工作台里根本不出现；参数面板空白。
- 18a 的「接口协议」下拉只在厂商声明了多个接口时才出现。中转站上它永远不出现，用户没有任何手段纠正。

## 二、新的交互逻辑（工程侧已定，设计须遵守）

1. **类型 chip 升格为"这是什么模型"的声明**，它决定「请求方式」区出现哪张协议菜单：对话 / 多模态 → 对话面菜单（18a 原样）；生图 → 生图面菜单；视频 → 视频面菜单。
2. **自动仍是默认，且不落字段**（18a 写盘约定原样）。自动解析的结果照旧用「自动 · 当前解析为 X」说出来。
3. 生图 / 视频菜单的条目随渠道类型不同，通常 1–4 项。名称与说明为暂定，可改：

   | 条目 | 第二行说明 | 出现在 |
   | --- | --- | --- |
   | 对话出图 | 图片随对话回复返回，多数中转站用这种方式 | 所有渠道的生图菜单 |
   | Images API | OpenAI 图像接口，gpt-image 系列 | OpenAI 官方与 OpenAI 兼容中转 |
   | Imagen | Google 独立生图接口 | Gemini 官方与中转 |
   | Videos API | OpenAI 视频任务接口（Sora 形态） | OpenAI 官方与 OpenAI 兼容中转 |
   | Veo | Google 视频任务接口 | Gemini 官方与中转 |
   | 同步生成 / 异步任务 | 18a 原文 | 阿里云百炼 |
   | xAI 图像、MiniMax 图像、MiniMax 视频等 | 目前是未翻译的技术名，需要补用户语言名 | 对应厂商 |

4. **协议决定参数。** 选了哪个接口，工作台就显示那个接口的参数（尺寸、比例、参考图上限、时长……）。模型 ID 能识别时，用该模型自己的参数表；识别不了时，用所选接口的默认参数表。
5. **在对话框里切换类型 chip**：已选的协议回到自动；切回原类型时恢复刚才的选择（只在本次打开期间有效）。不弹确认。
6. **协议失效（18a 态④）多了一种成因：类型改了。** 表现与态④相同：打开时显形、辅助色说明句、保存时静默清空。
7. **渠道本身没有该类型接口时**（例：Anthropic 格式中转上把类型设为视频；DeepSeek 渠道），模型仍可保存，但工作台里用不了。

## 三、需要的帧

主样例渠道：「NewAPI 中转」，渠道类型 OpenAI 兼容。默认双栏 1000 宽、亮色。

- **20a · 态⑤ 已识别 · 生图自动**
  `gpt-image-1`，类型生图。菜单 2 项（Images API / 对话出图），自动解析为 Images API。与态②同构，用来确认生图菜单和对话菜单是同一个控件、同一种双行条目。

- **20b · 态⑥ 未识别 · 按渠道默认**
  `nano-banana-pro`，类型生图，自动解析为「对话出图」。
  要有一句话告诉用户：这个 ID 没认出来，按渠道默认方式发送；如果中转站用的是 Images API，请手动选择。语气同帮助文字，不是警告。
  同时让用户知道参数面板会是什么样（未识别 + 对话出图 ＝ 没有专属参数）。

- **20c · 态⑦ 未识别 · 显式点单**
  同一模型，点了 Images API。点单态视觉沿用态③（描边主色、底主色 8%、引导线主色 35%）。
  受它管辖的下级行里，新增一行说明参数表的来源，例如「参数：按「Images API」默认（尺寸 · 质量 · 参考图上限）」。请设计这一行的形态，它对应 18a「联动」示意里的说明行。

- **20d · 态⑧ 视频未识别**

  这里有一个规则冲突需要你裁决：18a 态①规定"菜单仅 1 项时协议区不存在"，但未识别 ID 即使只有 1 项，用户也需要看到"按什么方式发送"。请决定这种情况下协议区是否出现、以什么形态出现，并在标注里写明规则。

- **20e · 态⑨ 渠道不提供该类型接口**

## 四、硬约束

- **几何**：弹窗 radius 16；输入与下拉用「大号」h 40、radius 8、值 13/500；chip radius 6、h 22；区块间距 24（双栏 20）；引导线缩进 12、宽 2px。字段标题在框上方独立一行，不用浮动标签；下拉尾部箭头用 expand_more。
- **类型 chip**：保持现在的 pill + 类型色圆点。
- **色彩**：不新增语义色。点单＝主色；失效与未识别说明＝辅助文字色；被忽略项＝次文字 + 不透明度 .55。不用警告色，不加图标底板。
- **文字**：不用 emoji。协议名走一份枚举 → 显示名的映射表，正文里的协议名加「」、不参与句子变形。
- **四语言**：简中、繁中、日、英，为日文和英文预留长度。按 18a 末尾的格式，把本轮新增文案列成一份 l10n 提取清单。
- **协议名的语言**：18a 定过"协议名说用户的话，不说接口黑话"。但中转用户需要对照中转站文档里的路径（如 `/v1/images/generations`）。请决定：第二行说明里要不要带 mono 路径，并写明理由。
- **三档宽度都要成立**：双栏 1000（窗口 ≥ 1100）、单栏 620、手机全屏。
