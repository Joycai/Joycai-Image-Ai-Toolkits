# 键盘快捷键 · 整体规划

**分期**：第一期 = 应用级 + 工作台 + 文件浏览器（本文件）。第二、三期只在 §9 登记，不开工。

第一期的理由：这三处是唯一有**文件管理操作**的地方，而工作台与文件浏览器对同一批动作
（预览 / 改名 / 删除 / 全选 / 清空选区）目前一个有键一个没键、一个走废纸篓一个直接抹掉。
键位不统一是表象，底下是两套实现，所以这一期同时是一次小的归一。

设计稿：Claude Design `00f 键盘快捷键`（见 §8 的 brief），00 系列 = 跨屏约定，与
`00d 拖放与落点`、`00e 工具头统一` 同族。

### 1a 两个已验证的缺陷（本期必修）

**① 点过目录树之后，`Delete` / `F2` 被文件夹抢走，且再也还不回来。**
文件卡是 `Listener`+`GestureDetector`，不可获焦；点树行会 `requestFocus()`
（`directory_tree_item.dart:498`）。实测（临时探针，跑完已删）：点文件夹 → 在网格里选 3 个文件 →
按 `Delete`，弹出的是「移除文件夹？确定要从列表中移除"browser"吗？」，选区纹丝不动；按 `F2`
打开的是树的行内改名框。回点网格**不会**把焦点要回来（`primaryFocus` 仍是 `directory-tree-row`），
所以这个状态持续到焦点被别的东西拿走为止。树行还没有任何焦点态视觉。

**② `⌘F` / `F5` 排在「文本框让位」判断之前，会提交半截的文件夹名。**
`_handleKeyEvent` 里这两条写在 `isTextEditingFocused()` 闸门**上面**
（`file_browser_screen.dart:197` vs `:224`），而行内改名编辑器失焦即提交
（`folder_name_editor.dart:96` `_submit(fromBlur: true)`）。改名途中按 `⌘F`，焦点跳去搜索框，
名字按当前输入落库。

### 1b 一个顺带清掉的债

工作台的删除（`gallery_file_actions.dart:96` `confirmAndDeleteImageFile`）是一套独立实现：
Windows 上 PowerShell 进回收站，**macOS / Linux 上 `File.delete()` 直接永久删除**，单文件，
确认框只有一行字。浏览器那边是 `FileDeleteService` + `TrashService`：有废纸篓走废纸篓、没有才永久，
批量、逐条失败不拖垮整批、执行时重新自证。两个键要统一，前提是两个删除先统一（§4 · D3）。

## 2 三层模型（这是规划的骨架）

一个键归谁，看它在这三层的哪一层。**认领顺序是从下往上**：焦点区先答，屏幕后答，应用层最后。

| 层 | 何时生效 | 注册在哪 | 例子 |
|---|---|---|---|
| **L0 应用** | 无论焦点在哪，只要本窗口最前、当前路由是最前、非移动平台 | `HardwareKeyboard` handler（`main.dart` 现有那个） | `⌘1…8` · `⌘/` · `⌘,` |
| **L1 屏幕** | 该屏在最前，且**文本框没拿着键盘** | 屏幕根部的 `Focus.onKeyEvent` | `⌘F` · `F5`/`⌘R` · `⌘\` · `Esc` 阶梯 · 工具标签直达 |
| **L2 焦点区** | 该区是当前焦点区 | 每个区一个 `FocusNode` + `onKeyEvent` | 选区类全部：`Enter` · `F2` · `Delete` · `⌘A` · `Shift+点击` |

**三条纪律**，写进 `docs/architecture/`：

1. **选区类的键归 L2，不归 L1。** 这是缺陷 ① 的根治：今天的冲突来自「树在 L2 认领 Delete，
   网格的 Delete 却在 L1」——同一个动作分居两层，谁先拿到焦点谁赢。全部下放到 L2 之后，
   「Delete 删什么」永远等于「现在是哪个区」，一个问题一个答案。
2. **L1 在认领任何键之前，先过 `isTextEditingFocused()` 闸门。** 缺陷 ② 就是闸门被两条越过。
   闸门之上只允许放「与文本无关且必须随时可用」的键——目前一条也没有，所以规则是：**没有例外**。
3. **L0 只放不依赖任何选区、任何屏幕状态的键。** 今天的 `⌘1…8` 合格；`⌘/`、`⌘,` 同理。

### 2a 焦点区（pane）模型

第一期给两屏各自划区，每区一个 pane 级 `FocusNode`（**不是每张卡一个**——几百个 FocusNode
既费又会污染 Tab 遍历，而方向键导航要到第二期才做）：

- 文件浏览器：`tree`（目录树）· `grid`（文件网格）· `staging`（暂存栏）
- 工作台：`tree`（侧栏目录树）· `grid`（画廊）· `config`（右栏参数，本期不认领任何键）

点击区内任意位置即 `requestFocus()` 到该区的 node（网格的空白处也算）。活动区要有**看得见的**
状态——设计稿定形（§8 帧 3）。没有活动区时（刚进屏、点了工具栏），L2 不作数，L1 照常。

### 2b `Esc` 阶梯

`Esc` 是唯一一个多义键，优先级写死并由测试钉住，自上而下第一个命中的接管：

1. 有浮层 / 浮窗 / 对话框 → 关掉它（各自已实现，L1 不插手）
2. 搜索框有焦点且有内容 → 清空并退出搜索
3. 当前活动区有选区 → 清空选区
4. 其余 → 不处理（让给上层）

## 3 一张注册表

`lib/core/app_shortcuts.dart`（core 层，纯数据 + 纯函数，已有先例：`text_editing_focus.dart`
就在 core 且 import `flutter/widgets`）。

一条记录 = `id` · `activators`（按平台给）· `scope`（L0 / L1+屏幕 / L2+区）· `labelKey`（l10n）·
`availability`（桌面 / 全平台）。三个消费方**只能**从这里读：

- 实现：`Focus.onKeyEvent` / `CallbackShortcuts` 的绑定
- 发现性：`⌘/` 面板、右键菜单的 trailing、设置页「键盘」一节
- 测试：唯一性（同一 scope 内不得有两条同 activator）、面板与注册表同源

**平台修饰键只有一个来源**：`AppShortcuts.primaryModifier`（macOS `⌘`，其余 `Ctrl`）。
今天 `main.dart:284`、`file_browser_screen.dart:196` 各写了一遍
`Platform.isMacOS ? isMetaPressed : isControlPressed`，`app_drag_session.dart:43` 还有第三套
（`⌥` vs `Ctrl`，那是拖拽复制键，语义不同，保留但登记在册）。

## 5 裁定

**D1 · 选区类键归 L2。** 理由见 §2 纪律 1。代价：浏览器现在 `_handleKeyEvent` 里的六条要搬家，
`browser_shortcut_scope_test` 要改写——那个测试钉的是「文本框活着时屏级快捷键整段让位」，
搬家之后这条依然成立且更强（网格不是活动区时根本不认领）。

**D2 · 工作台的 `Delete` 在「临时工作区」视图里是「移出工作区」，其余视图是「删除文件」。**
临时工作区是个篮子，篮子里的 Delete 是「从篮子里拿出来」，无损、可再拖进去、误按代价为零；
而「全部 / 已处理 / 文件夹」三个视图列的是磁盘上的文件，Delete 就该是删文件。
两种含义各自有确认口径：移出工作区只出 Snackbar，删文件走 D3 的确认框（框里写清是哪一种）。
**这是全表唯一一个同键两义，如果你不认，退路是：`Delete` 恒为删文件，移出工作区不绑键**
（选区条上那枚按钮留着）——改这一条只影响第 5 片。

**D3 · 工作台的删除改走 `FileDeleteService` + 浏览器同款确认框。** 不是为了好看：今天
macOS / Linux 上工作台是**直接永久删除**，浏览器是废纸篓，同一台机器同一批文件两种下场。
键位统一而实现不统一，等于把一个隐患变成一个更好按的隐患。确认框复用
`screens/browser/widgets/file_delete_dialog.dart`——它现在在 `screens/browser/` 下，
工作台不能横向引（层级规矩），所以这一片要把它下沉到 `widgets/files/`。

**D4 · `Enter` = 预览，`Space` 不绑。** `Space` 在预览里已经是「显隐控制条 / 视频播放暂停」，
在网格里再给它一个「快速查看」会让同一个键在相邻两屏两义。

**D5 · 不引入命令面板（`⌘K`）。** 本期没有可供搜索的命令表；等注册表存在一段时间、条目够多再谈。

**D6 · 真剪贴板（`⌘C`/`⌘X`/`⌘V` 搬文件）不做。** 浏览器已有「暂存 + 传输」这条完整的路
（`B1b` 稿），剪贴板是**第二条**路径，两条并存要先裁定它们的关系（暂存栏是不是剪贴板的 UI？
跨应用粘贴算不算？），那是独立一轮的事。本期 `⇧⌘C` 只复制**文件名**，不碰文件。

**D7 · 移动平台一律不注册。** 现状如此（`main.dart:282` 早退，浏览器整屏是受限页），外接键盘的
iPad 留到第二期，届时要单独想「没有 `⌘` 修饰键的物理键盘」。

**D8 · 不做方向键 / Tab 在网格里的导航。** 本期只建 pane 级焦点（它是方向键导航的地基）；
方向键要先定「网格的逻辑顺序是什么」（分组视图下跨组怎么走），配合无障碍一起做，登记在第二期。

## 6 发现性（不做等于没做）

今天除了 `⌘F`（浏览器头部）、`Enter`/`F2`/`Delete`（浏览器右键菜单 trailing）和助手输入框那行提示，
**没有任何地方告诉用户这些键存在**；工作台的右键菜单一个 trailing 都没有。

1. **`⌘/` 快捷键面板**：按「当前屏可用 / 全局」分区列出，数据来自注册表，所以不会和实现漂移。
2. **右键菜单 trailing 补齐**：浏览器补 `⇧⌘C` / `⌥⌘R` / `⌘O` / `⇧⌘N`；工作台全部补上。
3. **设置页「键盘」一节**：只读全表（自定义键位是第二期）。
4. **`AppKeyLabel`**（`widgets/ui/`）：按平台渲染键名（`⌘` / `Ctrl`、`⌫` / `Backspace`、`⌥` / `Alt`），
   面板、菜单 trailing、设置页三处共用。今天 trailing 是写死的英文字面量 `'F2'` / `'Delete'`。

## 8 设计稿 brief（`00f 键盘快捷键`）

给 Claude Design 的要求，**用本项目的组件词汇**（`App*` 包装件、玻璃件；只有没有包装件时才点名原生 Flutter 控件）：

- **帧 1 · 快捷键面板（桌面 1440）**：玻璃浮层，居中，最宽 720。分区：「当前页面」「文件操作」「全局」。
  每行 = 动作名 + 右对齐的键位徽标（`AppKeyLabel`，多键用 `+` 连接，`⌘` 等符号按 macOS/Windows 两版各画一遍）。
  面板顶部一行说明当前页面是谁。
- **帧 2 · 面板的窄态（834 / 390）**：平板收成单列；手机——按 D7 手机不注册快捷键，**这一帧要回答的是
  面板在手机上是否存在**（建议：不存在，设置页那一节也隐藏）。
- **帧 3 · 活动区的可见态**：同一张文件浏览器截图的三态（活动区 = 目录树 / 网格 / 暂存栏）。
  要求是「一眼看出键盘归谁」而不是「四条边都在发光」——给出边框 / 底色 / 行焦点环三选一的建议与理由。
- **帧 4 · 菜单 trailing**：右键菜单里键位徽标的排版（现在是裸文本 `F2`），含长键位（`⌥⌘R`）的对齐。
- **帧 5 · 设置页「键盘」一节**：只读列表，按 §4 的分组；预留第二期「自定义」的位置但本期不画控件。
- **规格汇总**：徽标的字号 / 内边距 / 圆角 / 用哪一层 ink，活动区态用的 token，面板的层级与遮罩。

注意：`00e 工具头统一` 已经定了工具头的构成，帧 3 / 帧 5 不要重画工具头；`A1b` 定了导航 chip 条。

## 10 已知的坑

- **`DefaultTextEditingShortcuts` 在屏级 handler 之上**：一个文本框没吃掉的键仍会上浮到 L1，
  所以 L1 抢走就等于字段永远收不到（这条已经记在 `2026-09-file-browser-file-delete` 的台账行里，
  缺陷 ② 说明它还会被违反——本轮把它变成结构约束，而不是靠记性）。
- **macOS 的 emacs 文本绑定**：`⌃A`/`⌃E`/`⌃F`/`⌃D` 在 macOS 上属于文本编辑。本表在 macOS 上一律用
  `⌘`，不要因为「Windows 上是 Ctrl」就在 macOS 上也发 `⌃`。
- **`Delete` 与 `⌫` 永远成对**：macOS 键盘上主区的那颗是 `⌫`。现有代码做对了，新增处照抄。
- **焦点节点是有成本的**：pane 级一个，不要下放到卡片（render perf 的规矩：先量再改）。
- **截图比像素不比字节**（`verification-gotchas`）：面板与活动区态的截图断言要按像素比。
